   - U：U特权级是否被访问
     - 隔离，保护操作系统
   - A：是否被访问过

   - D：是否被修改过
     - 页面换出时需不需要写回
   - RSW：
     - 预留给软件使用
   - PPN：
     - 保存物理物理页号
   - Reserved
     - 保留位

2. 缺页

   1. 缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。

      1. 请问哪些异常可能是缺页导致的？
         1. 页不存在
         2. 按需分配时尚未映射（未分配物理页）
      2. 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。
         1. S 特权级的一个名为 `satp` 的 CSR：记录当前页表根地址 + 模式，缺页的时候需要切换地址空间和映射模式
         2. 异常相关
            1. sstatus 特权级（S/U）
            2. sepc rap 发生之前执行的最后一条指令
            3. scause 异常原因
            4. stvec trap的入口地址

      缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。

   2. 这样做有哪些好处？

      其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。

   3. 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

      - 页数量：10G一个页能存4KB，10G/4kB = 10*2<sup>18</sup> 
      - 三级PTE：10*2<sup>9</sup> 
      - 二级PTE：10
      - 三级PTE：1
      - 占用内存：数量10*2<sup>9</sup> 和页表大小4kb相乘 
        - 大概 10\*2<sup>21</sup> 字节(20MB)

   4. 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

      1. 每个应用只加载固定的页
      2. 缺页时使用LRU换出最不常用的页

      缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。

      1. 此时页面失效如何表现在页表项(PTE)上？
         1. V：非法

3. 双页表与单页表

   为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说， 用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 [KPTI](https://en.wikipedia.org/wiki/Kernel_page-table_isolation) )

   - 在单页表情况下，如何更换页表？
     - 切换页表基址寄存器

   - 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）
     - 使用U来限制

   - 单页表有何优势？（回答合理即可）
     - 切换开销低，性能更好
       - 无需刷新TLB
       - 内核访问用户，无需转换

   - 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？
     - 双页表实现下，何时需要更换页表？
       - 内核用户态切换
       - 进程切换
